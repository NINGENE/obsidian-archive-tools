## 最低限のフォルダ構成を確認

手動テスト用に、まず以下の構成を使う。

```text
ObsidianVault/
├─ 10_References/
│  └─ Images/
├─ 20_Authors/
├─ 40_Bases/
├─ 90_Templates/
├─ _assets/
│  └─ thumbnails/
└─ ArtArchive/
   ├─ originals/
   │  └─ images/
   ├─ logs/
   └─ metadata/
```

役割は以下。

|フォルダ|役割|
|---|---|
|`10_References/Images/`|画像資料ノートを置く|
|`20_Authors/`|作者ノートを置く|
|`40_Bases/`|Obsidian Bases用の一覧・ギャラリーを置く|
|`90_Templates/`|ノートテンプレートを置く|
|`_assets/thumbnails/`|Obsidian表示用のサムネイルを置く|
|`ArtArchive/originals/images/`|実画像を置く|
|`ArtArchive/logs/`|将来の取り込みログを置く|
|`ArtArchive/metadata/`|将来のID管理や補助情報を置く|

現時点では、手動テストを優先するため、実画像もVault内の `ArtArchive/` に置く。

## ID方針を見直し

当初は `AA-000001` のような仮IDを使っていたが、今後は資料ノート用IDとして `REF` プレフィックスを使う方針にした。

資料ノートのID形式：

```text
REF-YYYYMMDD-HHMMSS
```

例：

```text
REF-20260622-143012
```

理由：

- `AA` よりも資料ノートであることが分かりやすい
    
- 日時ベースなので重複しにくい
    
- 連番管理ファイルがなくても運用しやすい
    
- Python自動化しやすい
    

その他のノート種別には、将来的に以下のプレフィックスを使う方針。

```text
REF   = 資料ノート / Reference
AUTH  = 作者ノート / Author
WORK  = 作品ノート / Work
CHAR  = キャラクターノート / Character
```

資料ノートは数が多くなるため、ファイル名もIDベースにする。

作者・作品・キャラクターのノートは、人間が探しやすいように名前ベースのファイル名にし、IDはfrontmatter内に持たせる。

## 実画像とサムネイルの命名ルールを整理

元画像がjpgの場合、実画像とサムネイルが同名になる可能性があるため、サムネイルには `_thumb` を付ける方針にした。

例：

```text
実画像:
ArtArchive/originals/images/REF-20260622-143012.jpg

サムネイル:
_assets/thumbnails/REF-20260622-143012_thumb.jpg

資料ノート:
10_References/Images/REF-20260622-143012.md
```

理由：

- 実画像とサムネイルを見分けやすい
    
- Obsidianのリンク解決で混乱しにくい
    
- Bases formulaでサムネイルを組み立てやすい
    
- Python自動生成時に処理しやすい
    

---

## 作品名とキャラクター名の扱いを検討

Obsidianで手動テストしていて、作品名とキャラクター名をタグ以外で持たせたいと感じた。

作品名・キャラクター名をタグにすると、タグ一覧が膨らみやすく、タグ疲れにつながる可能性がある。

そのため、v1.3では専用プロパティとして追加する。

```yaml
work_title: ""
characters: []
```

例：

```yaml
work_title: "作品名"
characters:
  - "キャラクターA"
  - "キャラクターB"
```

役割分担は以下。

```text
work_title / characters = 固有名詞
tags = 特徴・用途・見た目
virtual_folders = 仮想フォルダ上の分類
memo = 曖昧な印象や補足
```

## metadata-template v1.3 を作成

v1.2は飛ばし、v1.1の手動テスト結果を反映して `metadata-template v1.3` を作成した。

v1.3の主な変更点：

- `REF-YYYYMMDD-HHMMSS` 形式のIDに変更
    
- サムネイル名を `_thumb.jpg` に変更
    
- `work_title` を追加
    
- `characters` を追加
    
- `tags` と `virtual_folders` を引き続き分離
    
- `cover` プロパティは使わず、Bases formula方式を検証する方針
    
- 実画像はVault内 `ArtArchive/originals/images/` に置く前提で手動テストする
    

テンプレート例：

```markdown
---
id: REF-20260622-143012
type: image
title: ""
original_filename: "original_image.jpg"
source_url: ""
author: ""
work_title: ""
characters: []
tags:
  - inbox
virtual_folders:
  - References/Unsorted
local_file: "ArtArchive/originals/images/REF-20260622-143012.jpg"
local_file_uri: ""
thumbnail: "_assets/thumbnails/REF-20260622-143012_thumb.jpg"
created: 2026-06-22
status: inbox
rating:
---

[![REF-20260622-143012](../../_assets/thumbnails/REF-20260622-143012_thumb.jpg)](../../ArtArchive/originals/images/REF-20260622-143012.jpg)

# メモ

# 気になったところ

# 使い道

# 仮想フォルダ

- References/Unsorted

# 元情報

- 元ファイル名: original_image.jpg
- 実画像: [開く](../../ArtArchive/originals/images/REF-20260622-143012.jpg)
- 実ファイルパス: `ArtArchive/originals/images/REF-20260622-143012.jpg`
- サムネイル: `_assets/thumbnails/REF-20260622-143012_thumb.jpg`
```

## Obsidian Bases用の方針

v1.3では `cover` プロパティは一旦使わない。

代わりに、Bases formulaでサムネイルパスを組み立てる方式を検証する。

サムネイル名の規則：

```text
file.basename + "_thumb.jpg"
```

Bases formula候補：

```yaml
formulas:
  thumb: image(file(link("[[_assets/thumbnails/" + file.basename + "_thumb.jpg]]")))
```

この方式が動けば、資料ノート側に `cover` を書かなくても、ノート名とサムネイル名の規則だけでカード表示できる。
