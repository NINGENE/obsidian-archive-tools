# Devlog - 2026-06-21

## 今日やったこと

### Obsidianを資料管理・自作管理ソフトのプロトタイプとして使う方針を確認

Obsidianで画像・動画・Web資料などを管理するにあたり、実データを頻繁に物理フォルダ移動するのではなく、Obsidian上のノート・メタデータ・サムネイル・リンクで管理する方向を再確認した。

現時点の基本方針は以下。

```text
実データは一箇所に置く
  ↓
Obsidian側ではノート・Property・サムネイル・リンクで管理
  ↓
tags / virtual_folders / author note / memo を使って分類・検索
  ↓
将来的な自作ファイル管理ソフトの仕様へつなげる
```

---

### Obsidianで仮想フォルダ化プラグインを検討

物理フォルダを動かさずに、ノートや資料を「仮想フォルダ」のように分類できる仕組みを検討した。

制作資料管理では、実際のファイル配置を変えるより、Obsidian上でだけ階層分類できる仕組みが欲しい。

### VirtFolderを試した感想

既存プラグインとして **VirtFolder** を試した。

VirtFolderは、Obsidian上で仮想的な階層構造を作れるプラグインで、考え方自体はかなり近い。

ただし、今回の用途では以下が気になった。

- フォルダー用のノートが増える
    
- Notes Explorerとの併用が難しそう
    
- 仮想フォルダ内の資料をギャラリー表示しにくい
    

特に、フォルダー用ノートが増える点は少し気になった。

知識管理やMOC用途なら便利そうだが、制作資料管理では「見たいのは資料ノート本体」であり、フォルダー管理用ノートが増えるとノイズになりそう。

また、Notes Explorerと併用してギャラリー表示できない点も大きい。

画像資料や参考資料を扱う場合、階層で分類できるだけでは不十分で、サムネイル付きで一覧できることが重要になる。

---

### 自作するならどうするか

自作プラグインを作る場合は、VirtFolderのようにフォルダー用ノートを作るのではなく、各資料ノートのPropertyに仮想フォルダ情報を持たせる方式が良さそう。

例：

```yaml
---
title: 夕方の路地
type: reference
thumbnail: assets/thumbs/ref_20260621_001.webp
asset_path: D:/ArtArchive/images/ref_20260621_001.jpg
vfolders:
  - 資料/背景/街/路地
  - 資料/ライティング/夕方
  - ましゅまろ/背景参考
---
```

このようにしておけば、実ファイルもObsidian上のノートも動かさずに、プラグイン側で仮想的なツリーを生成できる。

イメージ：

```text
資料
  背景
    街
      路地
  ライティング
    夕方

ましゅまろ
  背景参考
```

この仮想フォルダツリーを左側に表示し、選択したフォルダ内のノートを右側にサムネイル付きで表示する。

---

### 仮想フォルダプラグインのMVP案

ここでいうMVPは **Minimum Viable Product** の略。

日本語では「最小限の実用可能な製品」という意味。

完成版ではなく、まず方向性が正しいかを確認するための最小構成を指す。

今回の仮想フォルダプラグインであれば、最初のMVPは以下に絞る。

- `vfolders` propertyを読み取る
    
- スラッシュ区切りで仮想フォルダツリーを作る
    
- ツリーをクリックすると、その仮想フォルダ内のノートを表示する
    
- ノートをクリックして開ける
    
- 可能ならサムネイルも表示する
    

最初から以下までは入れない。

- D&D
    
- 複数選択
    
- PureRef連携
    
- サムネイル生成
    
- 外部ファイル操作
    
- 自動タグ付け
    
- 高度な検索
    

まずは **仮想フォルダ + ギャラリー表示** が本当に便利かを確認する。

### Obsidian Bases のギャラリー表示を検討

Obsidianの **Bases / Cards view** を使って、資料ノートをギャラリー表示できるか検討した。

当初は、資料ノートのfrontmatterに `cover` プロパティを追加し、Cards viewの画像表示に使う案を試した。

```yaml
cover: "[[_assets/thumbnails/AA-000001.jpg]]"
```

しかし、`cover` プロパティを作っただけでは期待通りに表示されなかった。

その後、Basesの **formula** を使ってサムネイル画像を生成・表示している事例があることを確認した。

今後は、`cover` プロパティを直接持たせる方式ではなく、Bases側のformulaでサムネイルパスを組み立てる方式を検証する。

検証候補：

```yaml
formulas:
  thumb: image(file(link("[[_assets/thumbnails/" + file.basename + ".jpg]]")))
```

この方式がうまく動けば、ノート側に `cover` プロパティを追加せず、ノート名・ID・サムネイル名の規則だけでギャラリー表示できる可能性がある。

現時点での位置づけ：

- Pythonで生成したノート確認に向いているか

### タグ運用の方針を整理

タグが増えすぎると管理が疲れるため、タグを過剰に増やさない方針にした。

今後の分類方針：

```text
tags = 厳選した検索軸
memo/body = あいまい検索・全文検索・将来のAI検索用
virtual_folders = 仮想フォルダ分類
author note = 作者単位のハブ
```

細かいニュアンスや印象はタグにしすぎず、本文メモに書く。

例：

```markdown
# メモ

手の形が自然。
少し斜め上からの構図で、キャラが強く見える。
服のシワはラフだが、シルエットが分かりやすい。
```

将来的には、本文メモを対象にして、

```text
自然な手
強そうな立ち絵
斜め上の構図
ラフだけどシルエットが良い
```

のような、あいまい検索・全文検索・AI検索に近い機能を検討したい。

### 作者ノートを早めに作る方針を確認

資料管理では作者単位で見返したくなる可能性が高いため、作者ノートを早めに作る方針にした。

資料ノート側では、将来的に以下のように作者ノートへリンクする想定。

```yaml
author: "[[作者名]]"
```

作者ノートに入れる項目候補：

```markdown
---
type: author
name: "作者名"
aliases:
  - ""
platforms:
  pixiv: ""
  x: ""
  website: ""
tags:
  - author
status: active
---

# メモ

# 作風・特徴

# 参考にしたい点

# 関連資料
```

作者ノートは、資料ノートと同じくObsidian内の情報ハブとして使う。

## 決定したこと

- VirtFolderは思想やUIの参考にはするが、そのまま本採用するかは保留
    
- 自作するなら、フォルダー用ノートを作らず、資料ノートのPropertyから仮想フォルダツリーを生成する方式が良さそう
    
- 仮想フォルダ情報は `vfolders` / `virtual_folders` のようなPropertyで管理する
    
- 理想は、左に仮想フォルダツリー、右にサムネイル付きギャラリー
    
- `cover` プロパティ方式は一旦保留し、Bases formulaによるサムネイル表示を検証する
    
- Notes Explorerを導入し、Basesと比較しながら一覧表示用途を検証する
    
- タグは増やしすぎず、細かい情報は本文メモに書く
    
- 将来的に本文メモを使ったあいまい検索・全文検索機能を検討する
    
- 作者ノートは早めに作り、資料ノートからリンクできるようにする
