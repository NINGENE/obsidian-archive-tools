### metadata-template v1.3 で手動登録テストを実施

`metadata-template v1.3` を使って、画像資料ノートを手動で作成した。

v1.3では、以下の方針を反映している。

- 資料IDを `REF-YYYYMMDD-HHMMSS` 形式にする
- 実画像とサムネイルを同じIDで紐付ける
- サムネイルには `_thumb.jpg` を付ける
- `thumbnail` プロパティを使う
- `work_title` / `characters` を追加する
- `tags` と `virtual_folders` を分離する
- 実画像は `ArtArchive/originals/images/` に置く
- サムネイルは `_assets/thumbnails/` に置く
- 資料ノートは `10_References/Images/` に置く

## Basesでサムネイル一覧表示を確認

Obsidian Basesで、複数の資料ノートを一覧表示し、サムネイルも表示できることを確認した。

当初は `cover` プロパティやBases formulaを使う案を検討していたが、新しいVaultで試したところ、`thumbnail` プロパティをImage propertyに指定するだけでサムネイル表示できた。

現時点の方針：

```text
thumbnail = Bases表示用 + Python/管理用のサムネイルパス
cover = 不要
Bases formula = 予備案として保留
```

これにより、metadata-template v1.3では `cover` プロパティを追加しなくてもよさそう。

## 写真資料で characters プロパティを試した

今回のテスト画像はイラストではなく写真だったため、`characters` プロパティに被写体名を入れてみた。

実際に試した結果、写真・小物・背景・車・バイク・場所なども扱うなら、`characters` だけでは意味が少し狭いと感じた。

今後の検討候補：

```yaml
work_title: ""
characters: []
subjects: []
```

役割案：

```text
work_title = 作品名・出典作品名
characters = キャラクター名
subjects = 被写体・物体・場所・固有名詞
```

v1.3ではまだ `characters` のまま試し、v1.4で `subjects` を追加するか検討する。
