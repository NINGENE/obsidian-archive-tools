# ファイル管理ソフトプロジェクト概要

作成日: 2026-06-16  
用途: GitHub `/docs/00_project_overview.md` / Obsidian用の入口メモ

---

## 1. プロジェクトの目的

画像・動画・3Dデータ・Web資料・Markdown・PDFなどを、フォルダ移動に依存せず整理できるクリエイター向けファイル管理環境を作る。

中心となる考え方は、**実データは一か所に固定し、分類はタグやメタデータで行う**こと。

これにより、Maya / Unity / Unreal Engine / PureRef / Obsidian などから参照しているファイルのリンク切れを防ぎつつ、後から柔軟に整理し直せる状態を目指す。

---

## 2. 解決したい課題

- フォルダを移動すると他アプリからの参照が切れる
- 1つの資料が複数カテゴリにまたがるとフォルダ分類しづらい
- PixivやWeb資料のURL・作者名・投稿日・保存日を残しにくい
- 画像だけでなく動画・HTML・Markdown・PDF・3D関連ファイルもまとめて扱いたい
- PureRefで見ている画像から、Obsidian上の詳細情報へ逆引きしたい
- ブラウザのタブを大量に開きっぱなしにせず、資料を保存・整理したい

---

## 3. 基本方針

### 実データは一か所に集約する

実ファイルはなるべく移動せず、固定のアーカイブ領域に保存する。

```text
ArtArchive/
  originals/
  thumbnails/
  notes/
  metadata/
```

### 整理はタグで行う

フォルダ階層ではなく、階層化タグやメタデータで分類する。

```text
#character
#character/female
#background/interior
#material/wood
#pose/action
#project/marshmallow
```

### 1資料 = 1ノート

Obsidianでは、1つの資料につき1つのMarkdownノートを作る。

ノートには以下を記録する。

- 実ファイルへのリンク
- サムネイル
- 出典URL
- 作者名
- 投稿日
- 保存日
- タグ
- メモ
- 関連プロジェクト

## 4. 現時点の運用方針

最初から独自アプリを作るのではなく、まずは既存ツールを組み合わせて運用する。

当面の方針は以下。

1. **Obsidian + PureRef + Python** で3か月ほど実運用する
2. 実際に不便な点を洗い出す
3. Pythonで取り込み・リネーム・サムネ生成・Markdown生成を自動化する
4. 仕様が固まった段階で、独自アプリ化を検討する

---

## 5. 各ツールの役割

### Obsidian

資料ごとのメタ情報・メモ・タグ・リンク管理を担当する。

主な役割:

- 1資料ごとのMarkdownノート管理
- タグ検索
- URL / 作者名 / 投稿日 / 保存日などの保存
- サムネイル表示
- 実ファイルへのリンク
- PureRefや外部アプリから辿るための情報ハブ

### PureRef

制作中に画像資料を並べて見るためのビジュアルボードとして使う。

主な役割:

- 実サイズ画像の参照
- イラスト・3D制作中のリファレンス表示
- Obsidianで管理している資料の視覚的な利用

課題として、PureRef上の画像からObsidianノートへ逆引きできる仕組みが必要。

### Python

自動化の中心。

想定する処理:

- ファイル取り込み
- ID生成
- リネーム
- サムネイル生成
- Markdownノート生成
- メタデータ保存
- Obsidian用リンク作成

まずはGUIではなく、シンプルなPythonスクリプトから始める。

### GitHub

仕様書・運用ルール・スクリプトの管理に使う。

想定リポジトリ:

```text
obsidian-archive-tools
```

管理するもの:

- README
- docs内の仕様書
- Pythonスクリプト
- 運用メモ
- Markdownまとめ
- 将来的な独自アプリ仕様

## 6. MVP案

最初に作る最小構成は、**画像取り込みPythonスクリプト**。

### MVPでやること

1. 指定フォルダに画像を置く
2. Pythonスクリプトを実行する
3. 自動で一意のIDを付ける
4. originalsへ保存またはリネームする
5. thumbnailsにサムネイルを作る
6. notesにMarkdownノートを作る
7. Obsidianから検索・閲覧できるようにする

### 生成されるMarkdown例

```markdown
# asset_20260616_001

![[../thumbnails/asset_20260616_001.jpg]]

## File

- Original: `../originals/asset_20260616_001.png`
- Thumbnail: `../thumbnails/asset_20260616_001.jpg`

## Source

- URL:
- Author:
- Posted:
- Saved: 2026-06-16

## Tags

#reference

## Memo


```

## 7. ID設計

PureRef、Obsidian、実ファイルをつなぐために、資料ごとに共通IDを持たせる。

例:

```text
asset_20260616_001
```

このIDを以下に共通で使う。

```text
originals/asset_20260616_001.png
thumbnails/asset_20260616_001.jpg
notes/asset_20260616_001.md
```

これにより、PureRef上でファイル名を見れば、対応するObsidianノートを探しやすくなる。

## 8. 参考にしているアプリ・考え方

### Allusion

作りたい方向性に近いが、画像やGIF中心で、動画・HTML・Markdown・PDF・3D関連ファイルまで扱うには不足がある。

### Apple写真アプリ

一覧性・検索性・タグ的な整理感が近い。  
ただし、これも基本的には写真・動画向けなので、制作資料全般の管理には独自拡張が必要。

## 11. 最終的に目指すもの

最終的には、以下のような制作資料管理アプリを目指す。

- 実データは移動せず安全に管理
- タグで柔軟に分類
- 画像・動画・PDF・HTML・Markdown・3D関連ファイルを扱える
- サムネイル一覧で直感的に探せる
- Obsidianのようにメモやリンクを持てる
- PureRefや制作ソフトと連携できる
- Mac / Windowsの両方で使える
- クリエイターの資料管理・制作補助に特化している

## 12. 現時点の結論

最初の開発対象は、**画像取り込み・ID付与・サムネイル生成・Markdownノート生成を行うPythonスクリプト**。
